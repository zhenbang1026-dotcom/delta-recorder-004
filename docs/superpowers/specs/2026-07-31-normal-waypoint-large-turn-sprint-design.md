# 普通自动中继点大角度转弯保持疾跑设计

## 背景与根因

最近一组寻路诊断日志显示，开启“转弯保持疾跑”和“越过普通点自动跳过”时，部分弯道仍会短暂停车。最新场次 `logs/寻路诊断/20260731_204623/steps.jsonl` 中存在多段 `动作=转向`，其角度差约为 `32°`、`58°`、`80°`、`90°`、`114°` 等。

`巡航脚本.py` 的执行器对 `转向` 动作会调用 `_停止前进()`，释放 `W/Shift`，然后只执行视角调整。现有“普通点转弯保持疾跑”仅处理近点的中小角度微调，没有覆盖大角度分支，因此弯道会出现停车。

## 目标

1. 开启“普通点转弯保持疾跑”时，普通自动中继点即使发生 `90°～120°` 急弯，也保持 `W+Shift` 前进。
2. 急弯视角修正继续使用现有连续视角控制器，保持限速、加速度和看门狗机制，避免瞬间大幅鼠标移动。
3. 不增加前瞻寻路，不修改路线文件，不改变坐标识别、角度识别和 YOLO 逻辑。
4. 精准点、动作点、路线段终点和最终点继续使用原有精确处理逻辑。
5. “越过普通点自动跳过”保持独立，不改变其开关语义。

## 方案

在巡航控制器中保留现有动作选择、近点保护和转向不收敛处理，然后增加一个最小范围的普通点转弯疾跑转换：

1. 仅当“普通点转弯保持疾跑”开启时转换。
2. 当前点必须同时满足：
   - `自动路线=True`；
   - 不是首点、最终点或路线段终点；
   - 不是精准点；
   - 没有路线动作。
3. 当原动作是 `转向` 时，转换为 `疾跑前进并微调`，保留原转向动作计算出的鼠标像素。
4. 当转向不收敛保护产生 `前进并微调` 时，仅对同一类普通自动中继点转换为 `疾跑前进并微调`，避免保护分支重新造成慢走。
5. 距离已经达到到点阈值时，仍优先执行切换下一个点，不强制疾跑转向。
6. 转换后的动作由现有 `Win32执行器` 执行：持续保持 `W/Shift`，并把鼠标修正交给 `连续视角控制器`。不新增第二套鼠标移动逻辑。

## 数据流

```text
读取状态
→ 选择动作
→ 近点保护
→ 转向不收敛保护
→ 判断普通自动中继点资格
→ 转换为疾跑前进并微调（必要时）
→ 记录诊断日志
→ 执行器保持 W/Shift 并连续修正视角
```

## 边界与失败处理

- 精准点、动作点、路线段终点和最终点不转换，防止门口、楼梯和终点精度下降。
- 非自动路线点不转换，保持手动角度路线原行为。
- 转向像素仍由现有自适应转向算法计算，连续控制器负责平滑输出；不直接注入新的瞬时鼠标移动。
- 若识别失败、紧急停止或路线动作执行异常，沿用当前巡航的异常处理和停止机制。
- 急弯越过普通点后的处理仍由“越过普通点自动跳过”决定，不在本功能中新增批量跳点。

## 测试设计

先新增失败测试，再实现代码：

1. 开启开关时，普通自动中继点在 `45°`、`90°`、`120°` 角差下，`转向` 应转换为 `疾跑前进并微调`。
2. 开启开关时，转向不收敛保护返回的 `前进并微调` 应转换为 `疾跑前进并微调`。
3. 关闭开关时，以上输入仍保持原来的 `转向` 或 `前进并微调`。
4. 精准点、动作点、路线段终点、最终点和非自动点即使角差很大，也不转换。
5. 执行器收到转换动作时保持移动键状态，不调用释放移动键的转向分支。
6. 运行完整 `pytest`，对核心 Python 文件执行 `py_compile`，并执行 `git diff --check`。
7. 实机复测一条含急弯的路线，确认日志中普通急弯不再出现停车型 `转向`，且精准点仍能到达。
