# 旧路线 Y 偏移验证设计

## 目标

在不修改原路线和程序代码的前提下，复制一条旧路线并统一调整路径点坐标，用实机回放验证当前录制器与旧路线之间的固定 Y 偏移。

## 输入与输出

- 源路线：`routes/主变电站右1出生点到井盖.jsonl`
- 测试路线：`routes/主变电站右1出生点到井盖_旧路线Y减11测试.jsonl`
- 源路线必须保持字节和哈希不变。
- 如果测试路线已经存在，实施时停止并报告，不覆盖现有文件。

## 转换规则

逐行读取 JSONL：

- 文件头及非路径点记录保持不变。
- 对每条 `type` 为 `point` 的记录执行 `y = y - 11`。
- `x`、`angle`、`auto`、`actions` 以及其他未知字段原样保留。
- 不调整动作内部的 `target_y_offset_px`、识图点击偏移或鼠标移动参数，因为这些属于屏幕交互坐标，不是大地图路径坐标。

## 验证标准

生成后必须自动验证：

1. 源文件 SHA256 与生成前一致。
2. 测试路线可被项目现有路线读取器正常加载。
3. 新旧路线的路径点数量、顺序和动作内容完全一致。
4. 每个对应路径点均满足 `新 x = 原 x`、`新 y = 原 y - 11`。
5. 当前 Git 已跟踪文件不产生修改；测试路线作为本地实测数据，不纳入提交。

## 实机判断

- 如果终点和路线整体恢复，确认偏移约为 `(0, -11)`，再设计 UI 级旧路线兼容模式。
- 如果仍沿同方向偏移，根据剩余大地图像素差继续增加绝对值。
- 如果越修越偏，说明方向相反，下一次测试改为 `Y + 11`。
- 本轮只改变一条复制路线，不批量转换其他旧路线。
